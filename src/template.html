2 · Cards

Cards have no dates or times. A card stays in effect until the custodian announces the next one. Day 21 on Card 4 is always the same code. Switch cards at least monthly, because daily codes repeat each month.

3 · Enrollment code

One QR code and passphrase, two uses:

  • Phone app at /card/ on this site: shows the card in effect on a phone, locked with a PIN.
  • Far-end printing at /print/ on this site: a far end prints its own full-page or badge cards, or saves them as PDF. Nothing is stored.

The QR code holds the whole key, locked with the passphrase you choose. Whoever has both can make any card.

Give the QR code and the passphrase separately: show the QR in person and say the passphrase out loud, or send them by different routes. Anyone who has both can produce valid codes.

5 · Self-test & algorithm spec

Algorithm spec. Any other implementation must match this exactly.

Key. 20 random bytes (160-bit) from the browser's cryptographic random generator, exchanged as RFC 4648 Base32. Key fingerprint = first 2 bytes of SHA-256(key), in hex.

Card label. "CARD-" + N for card number N (1, 2, 3…). Nothing depends on dates, times or time zones.

Daily order codes. For i = 0, 1, 2…: h = HMAC-SHA256(key, "VAUTH1-O|" + label + "|" + i); n = ((h[0]<<8)|h[1]) mod 676; code = letter[n div 26] + letter[n mod 26]. Duplicates within a card are skipped. The d-th distinct code is the code for day d of the month (1–31). Read aloud in NATO phonetics.

Challenge/response. Format letter-digit-letter (e.g. A3C), 6,760 possible values. h = HMAC-SHA256(key, "VAUTH1-R|" + label + "|" + CHALLENGE); n = ((h[0]<<16)|(h[1]<<8)|h[2]) mod 6760; response = letter[n div 260] + digit[(n div 26) mod 10] + letter[n mod 26]. Printed challenges use the same mapping on "VAUTH1-C|" + label + "|" + i, skipping duplicates.

Test vectors. Key = ASCII "12345678901234567890", Card 1: daily codes for days 1–3 = RZ, YB, WT; challenges 1–3 = A6A, W2F, X8O; challenge A3C → I7J. Fingerprint 6ED6.

Strength. A guessed order code has a 1 in 676 chance. A guessed response has a 1 in 6,760 chance. A daily code can be replayed by anyone who overhears it until the day ends, and it comes back on the same day next month on the same card. Struck challenge lines can't be replayed. This catches impersonators and pranksters, not a determined adversary with many attempts, so a failed code on a critical order always means confirm by another path.

Enrollment code (phone app at /card/, far-end printing at /print/). VAUTH1.salt.iterations.iv.ciphertext (base64url). AES-256-GCM, with the key derived by PBKDF2-SHA256 from the passphrase (310,000 iterations, 16-byte random salt). The plaintext is JSON holding the Base32 secret, fingerprint, key version and incident name. A code with an iteration count outside 100,000–2,000,000 is refused.

Operating rules. The custodian announces the card in effect ("Authentication: Card Four") and, across time zones or near midnight, the day. Strike every challenge line after use. If codes fail, first confirm the card and day. Switch to a new card at least monthly, when challenges run low, or when a card may be compromised. Rotate the key if a set of cards is lost.
